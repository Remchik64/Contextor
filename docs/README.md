## Источники истины

Разделение жёсткое. Документ, описывающий состояние, обязан быть проверяемым.

| Проблемы и приоритеты | `known-issues.md` (идентификаторы `ISSUE-NNN`) |

надо исправить.

согласованы. Подробнее — `JOURNAL.md`.

## Конвенции

### Метки достоверности

Используются в `known-issues.md` и `proxy/`:

| Метка | Значение |
|---|---|
| ✅ | Проверено запуском кода или чтением обеих сторон |
| ⚠️ | Сообщено аудитом, лично не перепроверялось |
| `SPEC` | Замысел. В коде этого нет |
| `EXISTS` | Есть в коде, с указанием `file:line` |
| `BROKEN` | Есть в коде, но не работает или работает не так, как заявлено |
| `DEAD` | Есть в коде, не вызывается ниоткуда |

### Идентификаторы проблем

Ссылайтесь на `ISSUE-NNN`, а не на номера строк: строки сдвигаются при правках.
Реестр — `known-issues.md`.

### Правило для новых документов

Ни одно утверждение о состоянии кода не должно остаться без одного из:

- идентификатора `ISSUE-NNN`;
- ссылки `file:line`;
- команды, которой это проверяется.

Если проверки нет — писать «не проверено». Это не бюрократия: именно отсутствие такого
правила привело к тому, что документация проекта четыре месяца описывала несуществующие
функции как работающие, а `architecture.md` начинался со слов «Здесь написано как есть,
без маркетинга», содержа при этом ChromaDB в качестве хранилища WARM и несуществующий
Dashboard.

## О `archive/`

Документы в архиве сохранены, а не удалены, по двум причинам: хронология нужна для
восстановления истории, а удаление необратимо. Каждый файл начинается с шапки,
объясняющей, почему его нельзя принимать за описание текущего состояния, и что читать
вместо него.

Если архив мешает — его можно удалить целиком: git хранит все предыдущие версии
(`git show <commit>:docs/HANDOFF.md`).
