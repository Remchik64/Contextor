## Какие проблемы реестра блокируют прокси

Ниже — только выборка под углом «что мешает прокси-режиму», с объяснением почему.
Доказательства и правки — в [`../known-issues.md`](../known-issues.md).

| ID | Почему блокирует прокси |
|---|---|
| `ISSUE-001` | Прокси стоит между чужими инструментами и моделью. Пока весь `storage/` можно уничтожить одним неаутентифицированным запросом, терять можно всё |
| `ISSUE-002` | Вся память на русском (или любом не-ASCII) уничтожается при перезапуске, а со второго сохранения теряется сессия целиком. Прокси без надёжной памяти бессмыслен |
| `ISSUE-003` | Внешние клиенты всегда присылают `system`, а при его наличии инжекция контекста не выполняется. Для целевого сценария память отключена по построению — **блокер номер один по функциональности** |
| `ISSUE-005` | Весь смысл прокси — управлять окном. Сейчас окно не измеряется в токенах, а `num_ctx` ничем не управляет |
| `ISSUE-012` | Прокси обязан отдавать поток. Сейчас `stream` захардкожен в `False` на прокси-пути, а SSE — заглушка |
| `ISSUE-011` | Клиент получает `HTTP 200` с пустым ответом вместо ошибки — интеграцию невозможно отладить |
| `ISSUE-022` | Бюджет считается токенизатором GPT-4, а не модели движка. Для механизма, чья суть в бюджете, это недопустимая погрешность |
| `ISSUE-015` | Провайдер эмбеддингов залипает на BM25 после одной сетевой ошибки — семантический поиск молча выключен до перезапуска |
| `ISSUE-010` | Факты протекают между сессиями: изоляция нарушена |
| `ISSUE-004` | Контур подкачки фактов недостижим. Если прокси опирается на подкачку — она мертва |

**Не блокируют, но искажают измерения:** `ISSUE-013`, `ISSUE-014` (RAG), `ISSUE-023`
(имя модели в ответе), `ISSUE-032` (бенчмарки).

**Не блокируют:** остальные проблемы реестра касаются самостоятельного чат-режима,
упаковки и тестов.

## Что в коде при этом можно переиспользовать

Не всё плохо: часть механизмов для прокси уже написана и лишь не подключена.

| Механизм | Где | Состояние |
|---|---|---|
| `ModelSwapManager` — выгрузка модели из VRAM | `utils/swap_manager.py:113,132` | Написан, **ноль вызовов**. Для эфемерного координатора это центральный механизм — см. `04-vram-economy.md` |
| `fit_messages_budget()` — обрезка под бюджет токенов | `utils/tokenizer.py:22` | Написана, **ноль вызовов** |
| `Summarizer._simple_compress()` — построение памяти без модели | `core/summarizer.py:87-121` | Написан, модуль не импортируется (`ISSUE-037`) |
| Прокси-путь в OpenAI-эндпоинте | `api/system.py:381-397` | Есть, но без памяти и с захардкоженным `stream: False` |
| `MemoryStorage` — индекс фактов **в RAM** | `core/memory/storage.py:205` | Работает; основа для «доставать из оперативной памяти» верная |
| Слой графа | `core/graph_builder.py:113` | Метод `search()` существует, а вызывается несуществующий `search_nodes` (`ISSUE-006`) — правка в одну строку |
| Связка координатор → генератор | `core/orchestrator.py:345` → `:705-708` | **Работает.** Порядок вызовов верный, память вручается генератору в момент сброса |
