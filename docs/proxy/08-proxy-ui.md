# 08 — Интерфейс настройки прокси

`SPEC` — если не помечено иначе. Документ описывает, что именно нужно настраивать, как
это устроено и какие ручки нужны на сервере.

---

## 1. Сначала — где живёт конфигурация

Это надо решить **до** интерфейса, иначе повторится текущая проблема.

`BROKEN` Сейчас конфиг ищется в шести местах по приоритету (`config_loader.py:118-153`):
переменная окружения → `%APPDATA%\Contextor\config.yaml` → XDG → текущий каталог → корень
проекта → `/etc`. На этой машине эффективен файл в AppData размером **72 байта**, а
репозиторный `config.yaml` (53 строки) **игнорируется целиком**. При этом
`PATCH /settings` пишет в найденный файл — то есть в AppData.

Результат: пользователь правит один файл, система читает другой. Это худший вид
интерфейса — тот, который молча не работает.

`SPEC` Для прокси принимаем противоположное решение:

1. **Один явный файл.** `--config` в командной строке, по умолчанию `./proxy.yaml`
   рядом с проектом. Никакого поиска по шести местам.
2. **Абсолютный путь виден в интерфейсе.** В шапке вкладки всегда показывается, какой
   именно файл редактируется.
3. **Интерфейс пишет в тот же файл, который читает.** Одна функция чтения и одна записи.
4. **Значения из окружения** (для Docker) имеют приоритет и помечаются в UI как
   «задано окружением, не редактируется».

Это дешевле сделать сразу, чем потом объяснять пользователям, почему настройка не
применяется.

## 2. Что настраивается

### 2.1 Подключение (главное, о чём вы спрашивали)

| Поле | Тип | Пример | Примечание |
|---|---|---|---|
| `provider` | выбор | `llamacpp` \| `ollama` \| `openai` | определяет эндпоинты и способ теста |
| `base_url` | строка | `http://127.0.0.1:8080` | без `/v1` на конце |
| `api_key` | строка (маскируется) | `sk-...` | опционально, для `openai` |
| `model` | строка + «загрузить список» | `qwen2.5-coder-7b` | имя уходит в движок как есть |
| `timeout_s` | число | `300` | для долгих генераций |
| `stream` | флаг | `true` | потоковая отдача клиенту |

`SPEC` Кнопка **«Проверить подключение»** обязательна. Что она делает:

1. `GET {base_url}/v1/models` — доступность и список моделей;
2. `GET {base_url}/props` (llama.cpp) — размер контекста, число слоёв, KV-голов;
3. `POST {base_url}/tokenize` с пробной строкой — **работает ли подсчёт токенов**
   (см. `07-model-free-memory.md`, раздел 3);
4. показывает результат списком: что прошло, что нет, и что из этого критично.

Третий пункт важнее, чем кажется: если `/tokenize` недоступен, бюджет будет считаться с
погрешностью, и об этом надо сказать прямо в интерфейсе, а не выяснять по переполнению
окна.

`VERIFY` Набор эндпоинтов зависит от версии `llama-server`. Кнопка теста должна
проверять их фактически и показывать, что доступно, а не полагаться на предположение.

### 2.2 Буфер

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `num_ctx` | выбор + своё значение | `8192` | 4096 / 8192 / 16384 / 32768 |
| `threshold_warn` | доля 0.1–0.95 | `0.60` | разрешить ENRICH |
| `threshold_soft` | доля | `0.75` | мягкое сжатие |
| `threshold_hard` | доля | `0.85` | жёсткое сжатие |
| `keep_turns` | число | `6` | сколько последних ходов оставлять |
| `reserve_tokens` | число \| `auto` | `auto` | место под ответ; `auto` = `max_tokens` запроса |

`SPEC` Валидация на сервере: `warn < soft < hard`, `hard ≤ 0.95`, `keep_turns ≥ 2`.
Поле `reserve_tokens` при значении `auto` берётся из запроса — иначе окно переполнится
ровно на длине ответа.

### 2.3 Токенизация

| Поле | Тип | По умолчанию |
|---|---|---|
| `tokenizer.source` | выбор | `engine` (\| `local` \| `estimate`) |
| `tokenizer.local_name` | строка | пусто |
| `tokenizer.margin_pct` | число | `15` (для `estimate`) |

### 2.4 Память

| Поле | Тип | По умолчанию |
|---|---|---|
| `memory.enabled` | флаг | `true` |
| `memory.ledger_path` | путь | `storage/proxy/<session>/ledger.json` |
| `memory.archive_path` | путь | `storage/proxy/<session>/history.jsonl` |
| `memory.max_facts` | число | `2000` |
| `memory.scan_recent_turns` | число | `10` |
| `memory.anchor_markers` | список строк | `#anchor:`, `TODO:`, `Decision:`, `Решение:` |

### 2.5 Контур запуска

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `listen.host` | строка | `127.0.0.1` | **не** `0.0.0.0` по умолчанию |
| `listen.port` | число | `7861` | отдельно от админки |
| `cors.allow_origins` | список | `["http://127.0.0.1:7860"]` | **не** `["*"]` |
| `log.level` | выбор | `INFO` | |

`BROKEN` Почему `127.0.0.1` и узкий CORS: сейчас сервер слушает `0.0.0.0` при
`allow_origins=["*"]` и полностью без аутентификации, из-за чего `DELETE` с
`%2E%2E` уничтожает `storage/` из браузера (разбор — `06-known-defects.md`, A.1). Для
прокси это недопустимо: он стоит между чужими инструментами и моделью.

## 3. Живая диагностика

Настройки без обратной связи бесполезны — пользователь не поймёт, работает ли механизм.
Поэтому вкладка должна показывать состояние, а не только поля.

### 3.1 Индикатор буфера

Главный элемент интерфейса. Горизонтальная полоса с отметками порогов:

```
Буфер:  ████████████████░░░░░░░░░░░░░░░░░░░  4 210 / 8 192 токенов  (51%)
         ↑0.60 warn        ↑0.75 soft   ↑0.85 hard
```

Обновляется на каждом запросе через `GET /api/v1/proxy/status`.

### 3.2 Счётчики

| Метрика | Что показывает |
|---|---|
| Запросов обработано | всего |
| Сжатий | сколько раз резали историю |
| Токенов выброшено | объём ушедшего в память |
| Фактов в ledger | уникальных адресов |
| Якорей | сколько закреплено |
| Время последнего сжатия | мс |
| Провайдер токенизации | `engine` / `local` / `estimate` |

### 3.3 Стоимость сжатия

`SPEC` Отдельная метрика, потому что сжатие ломает KV-кэш движка и стоит полного
prefill (`01-architecture.md`, раздел 5). Показывать: время до первого токена на запросе
сразу после сжатия против обычного. Это единственный способ понять реальную цену
выбранного порога.

### 3.4 Просмотр памяти

Таблица ledger: адрес, тип, версия, `seen_count`, последний ход, вес, размер. С поиском
по подстроке и фильтром по типу. Плюс отдельный блок «Якоря» с возможностью добавить,
отредактировать и удалить вручную — это надёжный путь без модели
(`07-model-free-memory.md`, раздел 6).

### 3.5 Калькулятор VRAM

`SPEC` Простая форма: `n_layers`, `n_kv_heads`, `head_dim`, `dtype`. На выходе — таблица
из `04-vram-economy.md`. Нужна, чтобы пользователь за минуту проверил, окупается ли схема
на его модели, вместо веры на слово. Значения по умолчанию подставляются из `/props`.

## 4. Ручки на сервере

`SPEC` Минимальный набор.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/proxy/config` | текущий конфиг + абсолютный путь к файлу |
| `PATCH` | `/api/v1/proxy/config` | частичное обновление, валидация, запись и перечитка |
| `POST` | `/api/v1/proxy/test` | проверка подключения (4 проверки из 2.1) |
| `GET` | `/api/v1/proxy/status` | заполнение буфера, счётчики, стоимость сжатия |
| `GET` | `/api/v1/proxy/ledger` | факты, пагинация, поиск |
| `GET`/`POST`/`DELETE` | `/api/v1/proxy/anchors[/{key}]` | ручное закрепление |
| `POST` | `/api/v1/proxy/compress` | принудительное сжатие — **для тестов** |

Требования к `PATCH`:

1. **Валидировать до записи.** `warn < soft < hard`, допустимые значения `num_ctx`,
   существование путей.
2. **Записывать и немедленно перечитывать.** Ответ должен содержать то, что реально
   вступило в силу, а не то, что прислал клиент.
3. **Возвращать diff.** Пользователь должен видеть, что изменилось.
4. **Не терять неизвестные поля.** Запись должна быть merge, а не заменой файла
   (иначе комментарии и чужие ключи исчезнут).

`BROKEN` Пункт 3 — прямая противоположность текущему поведению. Сейчас вкладка Settings
отправляет 7 значений в `POST /api/v1/config/reload`, **хендлер которого не принимает
тело** (`api/system.py:147-148`). Значения молча отбрасываются, а интерфейс рапортует
успех. Плюс `loadSettings()` читает ключи, которых сервер не возвращает, поэтому поля
всегда показывают захардкоженные `0.7 / 20 / 5`. Это ровно та ошибка, которую здесь
повторять нельзя: **эффективное значение должно приходить с сервера, а не быть дефолтом
на клиенте.**

## 5. Как встроить в существующий интерфейс

`EXISTS` Админка — ванильный JS без фреймворка: `static/index.html` (332 строки),
`static/js/app.js` (~1300), `static/css/style.css` (~1300). Вкладки: Chat, Memory,
Models, Settings, Logs (`index.html:18-32`).

`SPEC` Добавляется вкладка **Proxy** — новый пункт в существующую навигацию плюс новая
секция. Новый фреймворк не нужен, стиль и хелперы переиспользуются.

Структура вкладки:

```
┌─ Proxy ─────────────────────────────────────────────────────────┐
│ Конфиг: C:\...\proxy.yaml                    [Проверить связь]  │
├─ Подключение ───────────────────────────────────────────────────┤
│ Провайдер [llama.cpp ▾]  Адрес [http://127.0.0.1:8080     ]     │
│ Модель    [qwen2.5-coder-7b        ▾]  Таймаут [300]  [x] Поток │
├─ Буфер ─────────────────────────────────────────────────────────┤
│ Окно [8192 ▾]   warn [0.60]  soft [0.75]  hard [0.85]           │
│ Последних ходов [6]   Резерв [auto]                             │
│ ████████████░░░░░░░░░░░░  4 210 / 8 192   (51%)                 │
├─ Память ────────────────────────────────────────────────────────┤
│ [x] Включена   Максимум фактов [2000]   Сканировать ходов [10]  │
│ Якоря: 3   Фактов: 148   Сжатий: 2   [Открыть ledger]           │
├─ Калькулятор VRAM ──────────────────────────────────────────────┤
│ Слои [28]  KV-голов [4]  head_dim [128]  [fp16 ▾]  → 1.75 ГБ    │
└─────────────────────────────────────────────────────────────────┘
```

`SPEC` Эскиз логики (в стиле существующего `app.js`, без фреймворка):

```javascript
async function loadProxyConfig() {
  const cfg = await api('/api/v1/proxy/config');
  if (!cfg) return;
  // Значения приходят с сервера — не хардкодим дефолты на клиенте
  setVal('proxy-base-url', cfg.upstream.base_url);
  setVal('proxy-model',    cfg.upstream.model);
  setVal('proxy-num-ctx',  cfg.buffer.num_ctx);
  setVal('proxy-hard',     cfg.buffer.threshold_hard);
  document.getElementById('proxy-config-path').textContent = cfg.config_path;
}

async function saveProxyConfig() {
  const patch = { upstream: { base_url: getVal('proxy-base-url'), ... },
                  buffer:   { num_ctx: Number(getVal('proxy-num-ctx')), ... } };
  const res = await api('/api/v1/proxy/config', { method: 'PATCH', body: patch });
  // Показываем то, что РЕАЛЬНО вступило в силу, а не то, что отправили
  if (res && res.changed) { showDiff(res.changed); await loadProxyConfig(); }
}
```

`SPEC` Требования к клиенту, которых не хватает текущему `app.js`:

- `api()` не должен схлопывать любую ошибку в `null` — при сбое сохранения пользователь
  обязан это увидеть;
- после сохранения — обязательная перечитка с сервера (защита от «сохранил, но не
  применилось»);
- кнопка «Проверить связь» показывает результат по пунктам, а не «ОК/ошибка».

## 6. Отдельная страница или вкладка

`SPEC` Два варианта, рекомендация — первый.

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Вкладка в существующей админке** | переиспользует стиль, хелперы, навигацию; одно место для всего | админка сейчас пустая по смыслу (чат, которого в прокси-режиме нет) |
| Отдельная страница прокси | чище концептуально | дублирование стилей и кода, два интерфейса |

`SPEC` Рекомендация: вкладка в существующей админке, но **при выборе прокси-режима**
вкладки Chat и Models скрывать — в прокси-режиме у Contextor нет своей модели, и
показывать выбор модели генератора было бы прямым обманом пользователя.

## 7. Оценка

`SPEC`

| Шаг | Оценка |
|---|---|
| Единый конфиг + `--config` + перечитка | 0.5 дня |
| Ручки `config` / `status` / `test` | 1 день |
| Ручки `ledger` / `anchors` | 1 день |
| Вкладка Proxy: подключение и буфер | 1 день |
| Живая диагностика (полоса, счётчики, стоимость) | 0.5–1 день |
| Просмотр ledger и якоря | 1 день |
| Калькулятор VRAM | 0.3 дня |
| **Итого** | **~5–6 дней** |

`SPEC` Если сокращать — убрать просмотр ledger и калькулятор VRAM (это удобства), но
**не** кнопку проверки связи и **не** индикатор буфера: без них пользователь не понимает,
работает ли механизм вообще, и это обесценивает всё остальное.

## 8. Чего делать не надо

`SPEC` Список ошибок, которые уже есть в этом репозитории и которые в интерфейсе прокси
повторять нельзя:

1. **Принимать значения и молча их выбрасывать.** Сейчас так работает вся вкладка
   Settings (`api/system.py:147-148`).
2. **Показывать дефолт вместо реального значения.** Сейчас `loadSettings()` показывает
   `0.7 / 20 / 5`, которых в конфиге нет.
3. **Иметь два источника правды для конфига.** Сейчас AppData перекрывает репозиторный
   файл (`config_loader.py:127-142`).
4. **Обещать в документации то, чего нет в коде.** `README.md:78` и
   `architecture.md:118` заявляют «live-настройку CCI и лимитов памяти», которой не
   существует; `api_reference.md` описывает четыре эндпоинта, отдающих 404.
5. **Слушать `0.0.0.0` с `allow_origins=["*"]` без аутентификации.** Для прокси, стоящего
   между инструментами и моделью, это недопустимо.
